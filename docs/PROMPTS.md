# 可直接複製使用的提示詞（claude.ai 專案內使用）

專案裡沒有子代理，用「開新對話」扮演不同角色。**研究者與審查者必須是不同對話**，審查者不能看到研究者的推理過程，只看成品。

> 範圍已升級為「中華民國、台灣史」：大陸時期事件要加 `ctx:"中國大陸"`；先讀 docs/CONVERSATION_DIGEST.md。

## A. 研究者（開新對話貼這段，把【】換掉）
```
請讀專案知識庫的 CLAUDE.md、ROADMAP.md 與 history.js（看格式）。
任務：為「【時期名稱 起訖年】」研究事件與專題，輸出可直接貼進 src/history.js 的 H_RAW 條目，
以及 src/bgdata.js 的專題（格式依 CLAUDE.md）。
規則：
1. 先搜尋並實際讀取頁面，每則事件附真實可開的來源網址（優先官方：國史館、國家人權博物館、中研院、教育部辭典；其次中央社、Taipei Times、中研院學者文章、維基）。
2. 每則事件標 conf（verified／common／disputed）。各來源日期、數字不一致時，並列在 note，不要自行選邊。
3. 中性用語；各方稱謂放 aliases。不要把同一年發生的事寫成因果。
4. 查不到就寫「目前未見可引用來源」，不要編造，也不要用工作用語（如「本次未讀到」）。
5. 輸出完整可貼上的程式碼，並說明貼到哪個檔案的哪個位置；最後列出「查證不足清單」。
範圍已經我確認：【貼上你確認的事件清單】
```

## B. 審查者（開新對話；只貼成品，不貼研究過程）
```
你是獨立的史料審查員。請讀知識庫的 CLAUDE.md（品質流程）。以下是待審的 H_RAW 條目與專題：
【貼上成品】
請逐則檢查：(1) 日期、人名、數字有無事實錯誤，用搜尋對照官方或學術來源；(2) conf 標籤是否合理（有歧見者不可標 verified）；
(3) 用語是否中立、稱謂是否並列；(4) 有無把「同時發生」寫成因果或評價性語句；(5) 抽查至少 8 個來源網址是否能開且內容相符；
(6) 有無工作用語外洩到公開內容。
輸出：「必須修正」（附正確內容與來源網址）與「建議調整」，只列有證據的問題，不要自己改。
```

## C. 帶回 repo
把修正後的條目與專題貼給 Claude Code（在 repo 內）：「請把以下內容放進 src/，build、跑 tests/smoke.py、確認全期泳道圖出現新圓點後，commit 並部署。」
