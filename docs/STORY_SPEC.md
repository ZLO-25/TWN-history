# 故事導讀撰寫規格

每個背景專題（src/bgdata.js 的 `BG`）配一篇故事導讀，放在 `src/stories/<專題id>.js`，一檔一篇。
讀者是要拿網站去教別人的台灣繁體中文讀者：讀完要記得「發生了什麼、主角是誰、前因後果」。

## 檔案格式（一檔一個 `S({...})` 呼叫）
```js
S({
id:"e228",            // 必須等於專題 id
min:20,               // 閱讀分鐘數＝全文字數/350，四捨五入到整數
lead:"一兩句話：這篇故事要讓你搞懂什麼。",
cast:[                // 主角 3–6 位
  {name:"陳儀", p:"chen-yi", role:"台灣省行政長官，接收與事件處理的主政者"},
  {name:"林江邁", role:"在天馬茶房前被查緝的菸販"}   // 沒有人物卡就不寫 p
],
secs:[                // 依序：開場、前因、經過（可拆成多段，各段自訂標題）、影響、各方怎麼看
  {h:"開場：1947 年 2 月 27 日傍晚", t:`段落一……

段落二……（空一行＝新段落）`},
  {h:"前因：為什麼一件查緝案會擴大？", t:`……

\`\`\`
（ASCII 圖：放在三個反引號之間；template literal 內要寫成 \`\`\`）
\`\`\``}
],
keep:["要記住的第 1 件事","第 2 件","第 3 件"],
think:["討論題 1（可以拿去問學生）","討論題 2"],
src:[{t:"國史館：……",u:"https://..."}]
});
```

## 內文標記（只用這幾種，不要寫 HTML）
- 空一行＝新段落。`**粗體**` 可用於關鍵詞（少量）。
- ASCII 圖：前後各一行 ``` 包起來（因果、時間線、層級都畫；每篇至少 2 張圖）。
- 連人物卡：`[[p:chen-yi|陳儀]]`（id 見 docs/STORY_LINKS.txt）
- 連台灣史事件卡：`[[h:完整事件標題|顯示文字]]`，標題必須與 docs/STORY_LINKS.txt 逐字相同。
- 連其他專題：`[[bg:專題id|顯示文字]]`
- 每篇至少連 4 個站內事件／人物／專題。只連真的存在的 id，`node tests/check_stories.js` 會檢查。

## 長度（全文字數，含各段，不含來源）
- 長篇約 6,500–8,000 字（約 20 分）
- 中篇約 4,500–5,500 字（約 15 分）
- 短篇約 3,000–4,000 字（約 10 分）

## 寫法
- 故事化：用具體場景、人物的處境與選擇帶出事件，依時間推進；但**每個事實都要有來源支持，不可為了故事性虛構對白、心理活動或細節**。引用原話要有出處；沒有出處就用敘述，不加引號。
- 先讀該專題原文（src/bgdata.js）與相關事件卡（src/history.js 的 H_RAW），故事要與站內內容一致；站內已有的細節用連結帶過，不必整段重抄。
- 中性用語、各方稱謂並列（光復／終戰、日治／日據、遷台／播遷／撤退、國府／國民政府…）。
- 不把「同一年發生」寫成因果；因果圖只畫有史料或學界支持的因果，推論性的寫「有學者認為」並註明。
- 有爭議（死亡人數、責任歸屬、評價）一律並列各方說法與出處，不下結論，不把立場寫成事實。
- 不確定就寫不確定（如「各來源記載不一」「目前未見可引用來源」）。數字、日期、人名要逐一查證。
- 不可出現工作用語（本次、任務、所讀來源、未讀到、研究者、審查…）。
- 「各方怎麼看」一節必備；沒有實質爭議的題目，改寫「這件事怎麼被記住」。
- 來源 4–10 個，真實可開的網址，優先官方（國史館、國家人權博物館、中研院、教育部辭典、總統府、全國法規資料庫、文化部國家文化記憶庫、檔案管理局），其次學術文章、中央社、維基百科（可用但不要只用維基）。

## 自我檢查
寫完執行 `node tests/check_stories.js`（檢查格式、連結、字數、工作用語）。
